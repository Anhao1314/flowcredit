# FlowCredit Agent 体系规划 v0.1（草案 · 待讨论）

> **定位（2026-11-18 用户定稿）：AI 时代算力经营者的「风投评估」层（VC-grade evaluation）。**
> 主体服务对象是风投/基金与被评估的算力企业：把"这个 AI 算力生意的故事"变成**证据核验过的投资尽调**——经营真实性、单位经济、增长趋势、客户结构与证据强度，全部可反查。
> **口号**：Make AI Economics Verifiable —— No black boxes：结论由确定性引擎算出，AI 编不了，人做主，全程可查账。
> （信贷/对手方风险是延伸场景，不是主体——还款质量作为"收入质量"科目保留在评估内。）

状态：草案 v0.1.1（2026-11-18 增补 B2B 定位）。本文档是瘦身与后续开发的裁判标准；每一条新能力/删减都要回答"它让经营者离一份可核验的体检报告更近了吗"。

## 0. B 端定位（2026-11-18 用户强调）

**我们面向 B 端。** 用户不是"人"，是企业的岗位：

| 面 | 用户岗位 | 他们的任务 |
|---|---|---|
| 投资方 | **风投/基金的分析师与投委会** | 对 AI 算力赛道的标的做尽调：核验经营数据、识别证据缺口、支撑投决 |
| 融资方 | 被评估/拟融资的算力经营者（CEO/CFO） | 把经营事实整理成**可核验的投资材料**，减少尽调摩擦 |

由此改写五条设计决定：
1. **对话页 = 引导式材料收集与评估的工作界面**，不是聊天产品；聊天只是录入方式之一
2. **数据主权是硬要求**：会话/评估/档案必须服务端持久化（浏览器存储只是演示态），可导出、可删除——DPA/试点协议的前提
3. **交付物 = 带指纹的证据材料包**：可导出 JSON、可被资方 verify_claims 独立复验、可进入企业自己的授信流程
4. **API 与对话同等重要**：B 端客户多数会 API 集成（嵌入授信流水线），/api/v1 与 /chat 是同一能力的两个入口
5. **商业模式**：平台订阅 + 按监控对象/评估次数；试点前置 = 数据授权协议签署

## 1. Agent 形态总纲

**一个产品 agent（Risk Agent）+ 一个内部研究 agent（Quant Sidecar），同一灵魂，两个战场。**

| | Risk Agent（产品） | Quant Sidecar（研究） |
|---|---|---|
| 用户 | 算力经营者、资方、平台 | 内部研究员 |
| 任务 | AI 生意的验货 + 体检 + 证据 | 策略提案 → DSR 裁决 → 晋升门禁 |
| 工具 | 7 个风险工具（→9） | 5 个量化工具（封闭） |
| 前端 | **/chat 独立对话页（第一公民）** | console Chat |
| 输出 | 体检报告卡（Grade + 证据状态 + 缺口 + 指纹） | 裁决报告（pp-Sharpe/DSR） |

**角色定义**：Risk Agent 是**风投尽调官**——不是问答机器人，是"接单 + 验货 + 尽调"三位一体：接料（自然语言/CSV/JSON）→ 验料（grounding/白名单）→ 算数（确定性引擎）→ 出尽调报告 → **引导补证**（一次最多 3 问，按优先级）→ 每补一轮即时重评 → 投委会材料。

## 2. 核心旅程（风投尽调——产品主路径）

```
开场 → 讲生意（自然语言/CSV/JSON）
  → 尽调评估（即时，缺什么如实列）
  → 引导补证（一次最多 3 问 + 示例格式）
  → 每补一轮即时重评（会话草稿续传 ✓ 已有）
  → 《尽调报告卡》固化（Grade + evidenceStatus + 缺口 + 指纹 → 进入投委会材料）
  → 持续监控：同一标的多期评估，Grade/增长趋势档案
```

**验收标准（P1）**：一个真实标的用**纯自然语言 + 贴一份月度经营 CSV**，拿到 evidenceStatus 不再全空（attested 级）的尽调评估——投资方第一次有"数字核验过的经营事实表"可看，且同一标的的多期评估可对比。

## 3. 能力体系（对照现状）

### 已对齐（✅ 保持，不重做）
- agent 循环（7 工具、MAX_STEPS 4、会话草稿续传、降级、审计）
- parser v0.3（自然语言月度行、中文 R/C、口语词表、19 字段）
- 意图门（帮助/范围外/校验错）、双语言、独立对话页 /chat
- 确定性内核 v0.2.1 + evidence-status 分级 + 指纹体系

### 待建（按目标优先级）

| # | 能力 | 服务于 | 说明 |
|---|---|---|---|
| 1 | **证据连接器 v0.1** | A 面闭环 | 对话内贴月度 CSV → import_csv → sha256 attestation → evidenceStatus 升至 attested；decision 离开 insufficient-evidence 的唯一路径 |
| 2 | **引导式追问**（prompt v3） | A 面转化率 | requiredActions → agent 主动提问策略：一次最多 3 问、每问带示例格式、按 evidenceCoverage 优先级 |
| 3 | **体检报告卡固化** | A 面产出物 | 评估固化为可分享对象（分享链接或导出 JSON 卡）——"能拿去给资方看"是 A 面的价值闭环 |
| 4 | **经营者档案**（记忆层 L1→L0） | 复购与 B 面 | 同一经营者的多轮评估沉淀为档案；跨会话召回历史 Grade 变化 |
| 5 | `compare_drafts` 工具 | 漂移检测 | 两版草稿/两次评估对比（经营变化检测）——后置 |
| 6 | B 面尽调复验 | 资方 | verify_claims 工具已有；资方视角的复验报告——依赖 #3/#4 |

### 明确不做
自主授信/PD/限额、多租户、通用行业模型、实时流式交易面、LLM 写权威字段、自由多 agent 编排。
